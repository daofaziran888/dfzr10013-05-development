# 企业经营分析决策平台

面向企业高层管理的经营分析决策平台。覆盖经营指标看板、财务多维分析、销售漏斗洞察、客户画像构建、供应链效率监控、人力效能评估、经营预测模型、异常预警与决策建议推送的完整企业分析链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

```text
├── .gitignore

```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 人力效能：人员投入核算

人力效能评估原来只有部门人效指标记录，现在增加一层「人员投入核算」：读入员工任职区间、
工时上报和部门产出明细，按自然日切分有效期、折算投入，聚合成部门人效偏差数据集。
效能指标记录（`hr` 表）仍然保留，核算结果走独立的派生数据集。

### 原始台账

| 台账 | 内容 | 关键约束 |
| --- | --- | --- |
| 员工任职 | 员工号、部门、任职起止日、投入比例 | 同一员工可以有多段跨部门任职，区间可重叠 |
| 工时上报 | 员工号、日期、可用工时、实际上报工时 | 同一员工同一天只认一条，重复上报被隔离 |
| 部门产出 | 部门、日期、数量、单位 | 同部门同一天同单位只认一条；数量 0 表示真实零产出 |
| 行业均值 | 部门、均值、单位、适用周期、口径、来源 | 必须覆盖核算周期且单位一致才参与偏差计算 |

示例台账见 `backend/app/seed_hr.py`，覆盖月中转岗、半日兼任、任职区间交叠、
离职当天、整月未上报工时、有投入无产出、有产出无人员等场景。

### 核算口径

1. **有效期切分**：任职、工时、产出统一按自然日闭区间切分，首尾两天都计入；
   离职结束日当天在岗，次日起不再产生切片。
2. **投入折算**：部门当日分配工时 = 员工当日报工 × 该部门投入比例。
   同日比例合计 ≤ 1 时按比例分摊，剩余部分记为「未分配工时」；
   比例合计 > 1（区间交叠）时先归一化，多出的部分记为「归一化差额工时」，
   当天各部门投入合计永远等于实际报工，不会超过可用工时。
3. **分母与零值**：人效 = 部门产出 ÷ 部门分配工时。以下四种状态严格区分：
   - `分母为零`：有产出但无人员任职，或报工折算为 0，人效不计算；
   - `未上报工时`：有任职但整周期没有工时，分母无法确认；
   - `产出未上报`：有投入但周期内没有产出记录，不能按 0 处理；
   - `真实零产出`：产出记录明确上报为 0，人效为 0。
4. **完整性**：存在阻断问题、部分核算或不可核算部门时，批次结论为
   「数据未齐，不能形成完整评估」，不允许提前形成完整评估。
5. **闭合核对**：`分配工时 + 未分配工时 = 员工当日报工`，
   `台账工时 = 切片工时 + 无任职归属工时`；两项差额都为 0 才算与原始人力台账闭合。
   更正任职后若留下无任职归属的报工，会作为阻断问题列出，不会被悄悄摊进部门。

### 核算批次与报告附件

- 每次核算生成一个不可变批次（`EFF-0001` 起），保存台账快照、人员日期切片、
  部门汇总、区间交集、矛盾记录、行业口径和投入闭合核对。
- 更正任职或补报工时/产出入台账后，旧批次保留原快照；重新核算生成新批次，
  并给出相对前一批次的变化清单。重复补报同一天工时会被拒绝，避免继续核算时重复累计。
- 报告「生成报告」时引用部门人效偏差数据集（可指定批次，缺省取最近一次），
  把人员日期切片、部门汇总、行业口径固化成附件版本。附件自带原始依据快照，
  组织调整后旧附件仍可复算（`POST /api/report/{id}/attachments/{version}/recompute`）。
- 没有可用批次或批次不完整时，生成报告会明确拒绝，不生成空附件。

### 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/hr/source/assignments` | 员工任职区间 |
| PUT | `/api/hr/source/assignments/{id}` | 更正任职（只改台账） |
| GET/POST | `/api/hr/source/timesheets` | 工时明细 / 补报工时 |
| GET/POST | `/api/hr/source/outputs` | 部门产出明细 / 补报产出 |
| GET | `/api/hr/source/events` | 台账变更日志 |
| GET | `/api/hr/source/industry` | 行业均值口径 |
| POST | `/api/hr/efficiency/runs` | 执行一次核算（`period_start`/`period_end` 必填） |
| GET | `/api/hr/efficiency/batches` | 核算批次列表 |
| GET | `/api/hr/efficiency/batches/{id}` | 批次详情（部门汇总等） |
| GET | `/api/hr/efficiency/batches/{id}/slices` | 人员日期切片（可按员工/部门/日期/状态过滤） |
| GET | `/api/hr/efficiency/batches/{id}/source` | 批次引用的原始台账快照 |
| GET | `/api/hr/efficiency/batches/{id}/export` | 导出批次明细 |
| GET | `/api/hr/efficiency/deviations` | 部门人效偏差数据集（供报告等模块引用） |
| POST | `/api/report/{id}/actions` | 生成/分发/归档报告；生成时可传 `hr_batch` |
| GET | `/api/report/{id}/attachments/{version}` | 报告附件（切片 + 部门汇总 + 行业口径） |
| POST | `/api/report/{id}/attachments/{version}/recompute` | 用附件自身快照复算 |

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
- 核算、批次、附件等派生数据放在 `store.dataset_rows(...)`，不进入概览页的业务模块统计。
